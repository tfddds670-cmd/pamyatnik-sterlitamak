# Сайт ритуальной мастерской «Вечная память» — Стерлитамак

Готовый статический сайт: каталог памятников, услуги, венки и ритуальные товары, галерея работ,
цены, калькулятор стоимости, формы заявок, страница контактов и юридические документы.

Сделан по образцу сайтов-конкурентов в Стерлитамаке
([granit-pamyati.ru](https://sterlitamak.granit-pamyati.ru/),
[toruda-park.ru](https://sterlitamak.toruda-park.ru/)): тёмная «гранитная» палитра с золотом,
серифные заголовки, каталог с ценами «от», калькулятор, блоки доверия и гарантий.

---

## 1. Как открыть

Сайт статический — достаточно открыть `index.html` в браузере (двойной клик).
Все ссылки относительные, интернет не нужен.

Если хочется посмотреть «как на хостинге» (с корректными путями и локальным сервером):

```bash
cd memorial-sterlitamak
python3 -m http.server 8080
# затем открыть http://localhost:8080
```

## 2. Структура

```

├── catalog.html        каталог памятников с фильтрами и поиском
├── uslugi.html         услуги мастерской
├── tovary.html         венки, корзины, кресты, гробы, организация похорон
├── raboty.html         наши работы (галерея с лайтбоксом)
├── ceny.html           прайс-лист: памятники, работы, товары
├── kontakty.html       контакты, форма заявки, карта
├── politika.html       политика конфиденциальности (шаблон)
├── oferta.html         публичная оферта (шаблон)
├── assets/
│   ├── css/style.css   вся вёрстка и дизайн-система
│   ├── js/main.js      вся интерактивность
│   └── img/*.svg       28 изображений-заглушек
├── preview/            скриншоты для быстрого просмотра
└── tools/
    ├── build_pages.py  сборка HTML-страниц из одного шаблона
    ├── gen_images.py   генерация SVG-заглушек
    ├── shoot.py        скриншоты страниц (утилита разработки)
    └── shoot.mjs       то же через Chrome DevTools Protocol
```

**Важно:** HTML-файлы генерируются скриптом `tools/build_pages.py` — в нём шапка, подвал,
модальное окно и контент страниц описаны один раз. Если будете править HTML вручную,
скрипт больше не запускайте, иначе правки перезапишутся. Либо правьте только скрипт и
пересобирайте:

```bash
python3 tools/build_pages.py      # пересобрать HTML
python3 tools/gen_images.py       # перерисовать SVG-заглушки
```

## 3. Что обязательно заменить перед публикацией

| Где | Что | Сейчас |
|---|---|---|
| `tools/build_pages.py` → `SITE` | название, телефоны, e-mail, адрес, ИНН/ОГРНИП, ссылки на соцсети | демо-данные |
| `assets/img/*.svg` | изображения товаров и работ | стилизованные заглушки, не фото |
| Отзывы в `tools/build_pages.py` → `REVIEWS` | реальные отзывы клиентов | примерные тексты |
| Цены в `CATALOG`, `SERVICES`, `PRODUCTS` | актуальный прайс | рыночные ориентиры |
| `kontakty.html` | карта | заглушка со ссылкой на Яндекс.Карты |
| `politika.html`, `oferta.html` | тексты документов | типовые шаблоны, проверьте у юриста |

Контакты меняются в одном месте — в словаре `SITE` в начале `tools/build_pages.py`:

```python
SITE = {
    "name": "Вечная память",
    "phone": "+7 (3473) 00-00-00",
    ...
}
```

После правки — `python3 tools/build_pages.py`.

### Как заменить изображения на фотографии

Фотографии кладутся в `assets/img/` под теми же именами, что и SVG
(например `pamyatnik-klassika.jpg`), после чего в `tools/build_pages.py` меняется
расширение в словарях `CATALOG`, `SERVICES`, `PRODUCTS` и в списке `RABOTY`.
Пропорции лучше держать 4:3, ширину — от 900 px.

## 4. Подключение форм к почте или CRM

Сейчас формы работают в демонстрационном режиме: данные проверяются, но никуда не уходят
(пишутся в консоль браузера). Чтобы заявки приходили, укажите адрес обработчика в
`assets/js/main.js` в первой строке функции:

```js
var LEAD_ENDPOINT = '';   // ← укажите здесь свой адрес
```

Варианты:

1. **Свой обработчик на PHP** (подходит для обычного хостинга). Файл `send.php` рядом с `index.html`:

   ```php
   <?php
   $data = json_decode(file_get_contents('php://input'), true);
   if (!$data || empty($data['phone'])) { http_response_code(400); exit; }
   $body = "Имя: {$data['name']}\nТелефон: {$data['phone']}\nТема: {$data['topic']}\n"
         . "Комментарий: {$data['comment']}\nСтраница: {$data['page']}\n";
   mail('zakaz@vechnaya-pamyat.ru', 'Заявка с сайта', $body, 'Content-Type: text/plain; charset=utf-8');
   echo 'ok';
   ```

   и в `main.js`: `var LEAD_ENDPOINT = '/send.php';`

2. **Сторонний сервис** (Formspree, Getform и подобные) — просто вставьте их URL.
3. **Telegram-бот** — URL вида `https://api.telegram.org/bot<ТОКЕН>/sendMessage`
   потребует небольшой доработки (нужен chat_id и другой формат тела запроса).

## 5. Карта на странице контактов

В `kontakty.html` сейчас блок-заглушка со ссылкой на Яндекс.Карты. Чтобы вставить настоящую карту,
замените этот блок на iframe из [конструктора Яндекс.Карт](https://yandex.ru/map-constructor/):

```html
<iframe src="https://yandex.ru/map-widget/v1/?text=..." width="100%" height="380"
        frameborder="0" style="border:0"></iframe>
```

## 8. Как устроена вёрстка

- Дизайн-токены (цвета, радиусы, тени, шрифты) — в начале `assets/css/style.css` в `:root`.
- Компоненты: `.btn`, `.card`, `.chip`, `.feature`, `.step`, `.review`, `.faq__item`,
  `.price-table`, `.cta`, `.badge`, `.field`.
- Сетки: `.grid--2/3/4`, `.cards`, `.gallery`; на мобильных всё схлопывается в одну колонку.
- Анимации появления — класс `.reveal` + IntersectionObserver; без JS контент виден
  (класс `js` на `<html>` добавляется скриптом в `<head>`).

Интерактив в `assets/js/main.js`: мобильное меню, аккордеон FAQ, фильтры каталога и поиск,
калькулятор стоимости, лайтбокс галереи, модальные окна, маска телефона, валидация форм,
плавное появление блоков, кнопка «наверх».

## 10. Публикация на GitHub Pages

Репозиторий уже подготовлен: `git init` с веткой `main`, файлы добавлены в индекс,
рядом лежат `.gitignore` и `.nojekyll`. Осталось закоммитить и запушить.

```bash
cd memorial-sterlitamak

# один раз: представьтесь git (если ещё не настроено глобально)
git config user.name  "Ваше Имя"
git config user.email "you@example.com"

git commit -m "Сайт ритуальной мастерской: первая версия"
```

Создайте на github.com **пустой** репозиторий (без README и .gitignore), например
`pamyatnik-sterlitamak`, и свяжите его с локальной папкой:

```bash
git remote add origin https://github.com/ВАШ-ЛОГИН/pamyatnik-sterlitamak.git
git push -u origin main
```

Затем в репозитории: **Settings → Pages → Source: Deploy from a branch →
Branch: `main`, папка `/ (root)` → Save**. Через 1–2 минуты сайт будет доступен по адресу
`https://ВАШ-ЛОГИН.github.io/pamyatnik-sterlitamak/`.

Почему репозиторий собран именно так:

- **корень репозитория = корень сайта** — Pages отдаёт `index.html` сразу, без настройки папок;
- `.nojekyll` отключает обработку Jekyll: деплой быстрее, файлы отдаются как есть;
- все ссылки в разметке и CSS относительные, поэтому сайт корректно работает и в подпапке
  `/<репозиторий>/`, и на собственном домене.

Обновление после правок:

```bash
python3 tools/build_pages.py        # если правили тексты в build_pages.py
git add -A && git commit -m "Обновил цены" && git push
```

### Индексация в поисковиках

Сейчас в проекте вымышленные контакты, цены и отзывы, поэтому демо-версия **закрыта от
поисковиков**: на всех страницах стоит `<meta name="robots" content="noindex, nofollow">`.
Управляется это одной строкой в `tools/build_pages.py`:

```python
NOINDEX = True      # демо: закрыто от поиска. Для боевого сайта поставьте False
SITE_URL = "https://tfddds670-cmd.github.io/pamyatnik-sterlitamak"   # отсюда берётся sitemap.xml
```

Перед публикацией «в бой» замените `True` на `False`, подставьте свой домен в `SITE_URL`
и пересоберите страницы:

```bash
python3 tools/build_pages.py
```

При сборке автоматически создаётся `sitemap.xml` со всеми девятью страницами.

**Почему не `robots.txt`.** Файл `robots.txt` поисковики читают только в корне домена.
Сайт на GitHub Pages лежит в подпапке (`tfddds670-cmd.github.io/pamyatnik-sterlitamak/`),
а корень `tfddds670-cmd.github.io` вам не принадлежит — `robots.txt`, положенный в корень
репозитория, будет проигнорирован. Мета-тег `noindex` работает на любой глубине.
`robots.txt` понадобится, когда переедете на собственный домен — тогда положите его в корень:

```
User-agent: *
Allow: /
Sitemap: https://ваш-домен.ru/sitemap.xml
```

### Свой домен вместо адреса github.io

1. Купите домен (например `pamyatnik-sterlitamak.ru`).
2. В **Settings → Pages → Custom domain** укажите его.
3. У регистратора домена создайте записи, которые подскажет GitHub
   (обычно `A` на IP GitHub Pages и `CNAME` для `www`).
4. Поставьте галочку **Enforce HTTPS**.

Для бизнес-сайта в России всё же стоит рассмотреть российский хостинг
(Timeweb, Beget, Reg.ru) с собственным доменом: Яндекс лучше ранжирует свой домен,
чем `*.github.io`, а скорость отдачи из РФ выше.
